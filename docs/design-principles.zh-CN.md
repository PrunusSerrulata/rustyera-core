# 设计原则

当需求发生冲突时，RustyEra 按以下顺序裁决：

1. 跨客户端与跨平台支持；
2. 架构纯净；
3. 与固定 Emuera 参考实现严格保持行为一致。

这一顺序只是冲突裁决规则，不代表可以忽略参考实现。只要不违背更高优先级，
EraBasic 游戏规则、输入判定、状态变化和其他脚本可观察副作用都应与参考实现一致。
所有有意差异都必须记录；涉及可执行行为时，还必须由稳定测试覆盖。

## 跨客户端语义

runtime 持有规范化的语义展示模型，用于描述逻辑文本、样式、按钮、对齐单元格、
分隔线、场景、资源、交互和一次性效果，但不嵌入 WinForms、GDI、操作系统设备对象
或像素缓存。每个前端把同一份权威模型投影到自己的 GUI、TUI、无障碍树或远程协议。

规范化展示记录游戏想表达的语义，而不是某个前端已经实现的物理排版。它可以包含
逻辑内容、样式、交互 token、布局约束和脚本定义的坐标空间，但不能包含由前端字体
引擎、viewport、DPI 或绘制实现产生的位置、换行、光栅缓存和物理历史。脚本定义的
媒体坐标属于逻辑展示数据，不等于设备像素坐标。

当参考行为依赖特定 renderer、字体度量、输入 API 或平台能力时，应先识别脚本作者
意图和游戏可观察语义。runtime 保留可移植语义，前端负责设备相关渲染和输入采集；
像素级复刻不是项目目标。

EraBasic 操作可以显式观察前端环境或已实现的展示结果。这类结果是外部观察，而不是
规范化展示状态。runtime 通过有序、版本化服务请求从当前权威前端取得结果，并验证
身份、revision、操作版本和返回结构，但不复刻或解释前端的渲染算法。缺少能力时必须
返回明确的不支持结果，不能由 runtime 编造一个规范化近似值。

前端观察还必须与可移植资源事实区分。例如，按内容寻址的源图像尺寸和像素可以由
外部解码服务提供；已光栅化 canvas 的像素或文字尺寸则依赖前端投影。查询 runtime
持有的样式与对齐意图仍属于 runtime 操作。

## 可移植性与依赖投影的脚本

前端观察是有序的外部输入。执行只有在完整输入与服务响应轨迹相同的前提下才具有
确定性。等待观察结果属于临时外部等待，会阻止稳定快照和热替换提交。当前每个
runtime session 只有一个权威前端，由 session 信封、epoch、sequence 和观察 revision
共同标识。多客户端 session 和权威转移不在当前支持范围内，需要未来重新设计主版本
协议。

前端环境查询可以合理用于展示适配，例如检测字体后选择 ASCII art fallback，或按
viewport 选择布局。但依赖投影的结果不可移植，必须产生带源码位置的可移植性诊断。
如果该值影响持久游戏状态、会改变玩法的控制流、随机种子、动态调用、存档内容或其他
游戏内容，而不只是展示适配，则应报告更强的“仅兼容用途”诊断，并作为未来弃用候选。

弃用不能自动发生。它必须先有已记录的可移植替代方案、真实脚本用法审查，以及明确的
语言或协议版本迁移。在此之前，仍受支持的仅兼容操作应返回权威前端的真实结果，不得
静默近似或移除。

## 架构边界

runtime 是游戏状态、规则、超时、交互 token、session 顺序、存档和恢复的唯一权威。
它通过 Rust 接口驱动 VM；VM 不得从指令回调直接修改 runtime 状态。前端负责文件 I/O、
渲染、媒体播放、平台输入采集及设备/生命周期报告，并通过版本化消息与 runtime 交互，
不共享内部对象。

“唯一权威”不表示 runtime 可以制造外部事实。前端服务响应只有在 runtime 按 session
顺序接受后才对脚本可见；前端提供观察值，runtime 对后续验证和游戏状态变化保持权威。

可恢复展示状态与一次性效果相互分离。runtime 及其下层不调用 GUI、音频或文件系统
API。共享契约优先采用可移植、确定性的逻辑表示，不能泄漏具体客户端实现细节。

仓库中的 Python/Textual TUI 是公共 C ABI 的一个具体前端，但它主要用于验证参考行为、
真实游戏脚本和 C ABI 端到端可用性，不是终端排版质量或性能标杆。Rust runtime 仍不
依赖这一前端。

## 参考兼容性

固定的 Emuera 源码树仍是语言语法、语义和可移植 runtime 行为的 oracle。调查参考实现
也用于还原与 UI 耦合指令的意图。行为按以下类别记录：

- 已实现且兼容；
- 因更高优先级原则而有意不同；
- 以稳定错误明确表示不支持；
- 尚未实现。

兼容状态与可移植状态彼此独立。已实现操作还要分类为可移植、依赖前端环境、依赖前端
投影、仅兼容/不推荐、已弃用或不支持。一条指令可以与参考实现一致，同时仍不可移植并
需要诊断。

协议类型定义和 reference CLI endpoint 都不能证明 Rust 已实现对应能力。判断现状必须
结合具体实现、Rust 测试和真实脚本验证。

## 确定性与持久化格式

源码采用 UTF-8，源码位置使用 UTF-8 byte offset。语义输入相同时，编译产物必须保持
确定性。字节码、传统存档适配器和 VM snapshot 带有明确身份或版本，不兼容时必须拒绝
加载，不能猜测。集合、诊断和 wire 编码不得依赖随机 map 迭代顺序或未记录的客户端本地
状态。

消费时钟、输入、熵或前端观察服务的 runtime 执行，只有在有序外部响应轨迹相同时才
可复现。
