## 1. 目标、基线与已确认取舍

完成确定性 API、动态调用、算术/RNG 策略、输入状态机及错误钩子，为批次 3 的 SQL
和批次 4 的游戏闭环提供可验证契约。本批不承诺真实蛇版 TW 标题、地图或完整游戏可玩。

规划时三个专用 worktree 均干净且位于 `codex/snake-compatibility`；下表只记录规划基线，
实施及恢复时仍须核对各仓库分支、状态、worktree、实际产品输入与绑定。

批次 1 已完成约定范围；沿用其原始证据和已登记差异，不重复验收或将其解释为完整兼容。
规划阶段只读检查，未修改文件、运行产品测试或创建提交；本方案落盘不增加完成证据。

已确认的实施选择：

- **RNG**：统一使用可保存、可重放的 SFMT，正确实现 `DUMPRAND/INITRAND`。
  不复刻临时副本写入缺陷，不实现蛇版 `.NET Random` 双状态路径；明确不保证与开启
  `UseNewRandom` 的蛇版 TW 同 seed 同结果。
- **STRFORMCHECK**：保留实际展开及其副作用，修正旧计划中的“纯检查”描述。
- **TUI GETKEY**：不实现终端按键扩展；撤销无法真实提供的完整按键状态能力，明确诊断。
- **参考实现**：允许最小 headless 动画计时器接线修复，正常引擎语义与固定基准不变。
- **测试**：批次 2 各子批次不设测试总时限；唯一重构审查、单次全量、静态门禁、
  看门狗和证据要求保持不变。此授权不扩展其他批次或允许失败后重跑全量。

## 2. 规模划分与依赖

按共享实现和故障风险预先固定六个子批次，不按 API 数量拆分，也不在失败后重新划分。

## 3. 实施契约

### 2A：集中执行策略，保持优化前后一致

- 在 `erabasic-compat` 集中定义算术、实参和相关兼容策略，由 analyzer、HIR、compiler、
  VM、runtime 共同消费；不在各层散布独立 snake 判断。
- D07 覆盖常量折叠、普通表达式、复合赋值、自增自减、循环步进、动态表达式及优化路径。
  按固定参考逐操作实现，不能笼统把所有溢出都改成数学饱和；`MIN/-1` 和 postfix 边界
  单独保留 oracle 期望。
- `UNCHECKED_ADD/SUB/MUL/NEG` 始终使用明确的二补码 wrapping，与普通算术策略隔离。
  使用蛇版 `NOISE` 和原版 eraTW 的对应断面验证。
- 算术与多余实参告警采用稳定 code、位置和 generation 去重；常量折叠、暖缓存、memo
  不能吞掉应有诊断或重复制造告警。
  告警沿用跨端独立诊断通道，不注入脚本文本历史。固定蛇版会将运行期算术告警追加到
  显示历史；此处保留有意的展示及历史查询差异，不能把它仅归为诊断 Schema 不可比，
  也不能过滤其输出后声称匹配。逐例保留实际输出、诊断及原始差分结论；D08 的历史
  查询基于 Rust 规范化游戏历史，不包含这些诊断行。
- snake `TOINT` 对参考已确认的整数读取异常返回 0，不额外增加参考不存在的 warning；
  不改变 `ISNUMERIC` 或吞掉无关故障。
- XML 多目标 clone、字符串 `>=/<=` 当前已有实现：补双 oracle fixture，确认现有行为及
  参考差异，不为了制造 profile 分支而回退原版现有行为。
- RNG 复用现有 SFMT 实现及 625 项 RANDDATA 事务路径。所有随机调用、重播、snapshot、
  当前支持的保存/恢复操作同一权威状态；非法状态拒绝必须原子化。保留低 32 位 seed、
  取样顺序及状态格式测试。
- 升级实际发生变化的 snake policy/semantic identity，明确记录 RNG 有意差异。旧 snake
  cache 重建；不兼容 snapshot/身份容器明确拒绝，本批不提供静默迁移。原版 RNG、裸存档
  与 profile 行为保持。

### 2B：完整调用文本、惰性实参与真实格式检查

- `CALLSTR` 六变体接收一个字符串表达式，运行时解析完整的 `目标(实参...)` 或
  `目标, 实参...`；不是 `CALLFORM` 的名称别名。空白文本无操作，保留 TRY/CATCH、
  missing target、参数转换失败和 JUMP 栈展开边界。
  固定蛇版先构造并解析全部实参，再检查目标；随后对全部外层实参执行
  `Argument.Restructure`，最后转换为形参并执行。多余外层实参不做普通求值，但仍参与
  这一预处理，包括常量错误与少量方法的专有读取；嵌套用户方法先转换形参，因此其
  被截掉的实参不参与嵌套预处理。所有变量索引预处理完毕后才统一检查常量索引。
  此顺序不改变 D06 对普通实参求值的惰性要求；预处理错误不落入 CALLSTR 的绑定捕获。
- 复用已有动态表达式前端、调用方符号环境、REF、generation 和 continuation。仅支持
  现有 Integer/String 与数组 REF；不提前引入 Float、variadic、元素 REF、OUT 或通用 EVAL。
- D06 覆盖静态 CALL、CALLFORM、CALLSTR、直接方法、GETMETH/GETMETHS 和 STRFORM 内部方法。
  snake 非 variadic 多余实参不执行；不能先求值全部参数再截断。语法解析、名称解析与
  运行时求值分别保留正确错误边界。
- 内置函数 arity 不放宽。原版继续拒绝多余实参；snake 默认告警并执行，新增严格诊断
  配置可将该告警提升为错误。
- `EXISTVAR(name, 0)` 保留单参数 bitmask；非零模式按固定蛇版执行表达式解析，不读取
  storage cell、不额外验证实际访问越界。保留调用方 scope、ERD/ALS、REF 解析及参考中
  的参数求值顺序；Float bit 后置。
- `STRFORMCHECK`：字符串参数求值失败仍正常传播；随后解析并实际展开，成功返回 1，
  受捕获的脚本解析/展开错误返回 0，已发生副作用不回滚。复用正常服务权限与等待机制；
  取消、资源耗尽、坏字节码和协议故障不得伪装成普通检查失败。
- 捕获 continuation 必须正确恢复 caller、REF 和临时资源；被检查器捕获的错误不进入
  最终错误钩子。覆盖嵌套调用、异步服务、错误后继续执行及快照边界。
- 动态目标进入保守可达性和缓存依赖模型，不能仅记录第一次解析出的目标。缓存只复用
  解析/编译结果，不缓存具有副作用的执行结果；profile、调用方符号环境、generation
  或目标签名改变时失效。
  解析用的完整 builtin 名字表不授予执行权限。仅在动态文本中出现的 Native 方法也必须
  由编译器的实际 HostRegistry 授权、按 catalog 绑定参数，并找到真实 provider；不能依赖
  额外的静态占位调用，也不能为可变参数枚举无界的物理签名。

### 2C：数组、CSV、bit 与 MAP

- `MATCHALL/MATCHALLEX` 覆盖 Integer/String、范围、省略参数、角色数组及可选输出数组。
  结果为全部匹配数，输出容量不足只截断写入；保留 `MATCHALLEX` 对首参数形态的参考限制。
- 四个 `GETCSVNO*` 在同次摄取中保留原始姓名字段是否出现，并于 CALLNAME 回填前建立
  反向索引；按 NO 排序后逆序写入，正常比较域的重复名称由最小 NO 获胜，不能按文件
  加载顺序决定。缺失返回 `-1`，不增加大小写折叠；显式空字段和缺字段不混淆。
  固定参考以 `(int)(left.No-right.No)` 排序，极端 NO 会截断或失去全序；此处沿用可移植
  的 i64 安全总序，保留极端值差分用例并逐项登记实际参考结果，不复刻非传递比较器。
- bit API 使用明确的无符号位操作及 VM place 写回事务，覆盖跨 63/64 位、负索引、越界、
  长度、只读数组、REF 和角色存储。不得直接绕过 VM 内存与引用边界。
- MAP 扩展复用现有插入顺序；覆盖值不移动 key，self merge 先固定源集合，查询/过滤模式
  按参考实现。
- `MAP_TOSTRING/FROMSTRING` 保留蛇版分隔符格式，不新增转义。FROMSTRING 不先清空已有 MAP；
  round-trip 只承诺不含分隔符冲突的数据，冲突输入按参考结果测试并记录限制。
  MAP key 身份、contains/equality 保持 ordinal；前后缀及 FROMSTRING 的键值分隔符查找
  使用固定参考环境的 invariant-culture ICU 比较。嵌入固定数据，不使用宿主 locale。
  FROMSTRING 按 UTF-16 下标及分隔符字面长度逐条切分、立即写入；后续条目失败不回滚
  先前写入。切分产生孤立代理项时受本项目 UTF-8 字符串边界约束，明确报错并登记差异，
  不以替换字符静默改变 key/value。
- 所有输出数组、RESULT/RESULTS、副作用顺序、structured snapshot/GLOBAL 均走已有契约。

### 2D：错误钩子作为故障生命周期的一部分

- 仅 snake 启用 `BEFORE_THROW/BEFORE_ERROR`，映射已有蛇版禁用配置；默认允许，原版不触发。
- 最终 fault 前保存原始错误 code、位置、来源及关联 ID，再调度 hook。THROW 只进入
  BEFORE_THROW，不在结束时再次进入 BEFORE_ERROR。
- hook 正常结束仍报告原始错误；hook 自身失败保留原错误，附加 secondary fault，
  不覆盖、不递归触发。
- hook 可执行正常获准脚本和服务，但继续服从运行限额。取消、资源耗尽、无效字节码与
  内部安全故障不开放 hook 绕行。
- hook 执行期间拒绝 stable snapshot/reload；完成后保留现有 fault 后只读调试能力。
  不得从故障点恢复普通执行。

### 2E：规范化背景、历史查询和逻辑计时器

- S10 使用独立的**全局整行文本背景状态**，不复用 run 背景。开关应影响符合条件的已有
  历史行；保留 RGB、alpha 及行资格，Web/Tauri 按全宽投影，TUI 对透明度进行明确的
  颜色合成降级。
- 背景开关进入 snapshot/delta，覆盖虚拟化旧行、空白/按钮/图像/HTML 行以及 resize；
  不改变普通 `SETBGCOLOR`。
- D08 snake 负索引基于 runtime 的规范化历史行集合，包含 pending/flush、清行和裁剪边界；
  原版负数仍返回空串，极负值不得溢出。
- D10/S13 共用 `ResourceGraph` 的逻辑计时器：越过 `i32::MIN..=32767` 报错且状态不变；
  非正值停用，1–9 规范化为 10。GET 查询不读取渲染帧时间，也不能被常量折叠。
- 保留原版已支持的表达式/命令外形及一般表达式参数；snake 命令式 SETANIMETIMER 不改
  RESULT。BITMAP_CACHE_ENABLE 只处理语法和已有性能提示，不宣称实现后置缓存功能。
- 最小修复蛇版 headless 计时器设置/查询接线，逐文件追加 `HEADLESS_CHANGES.md`；
  不以当前跳过设置的 wrapper 返回值建立 golden。

### 2F：统一输入顺序、真实设备状态与环境查询

- 在现有输入状态机中加入 NF 展示策略、单个 pending sequence、macro-enabled 和设备
  latch，不另建前端输入解释器。
- `SEQUENCEINPUT` 是单槽位，后写覆盖前写；实际进入等待时先清槽，再走普通文本提交路径。
  保留已有 undo/replay 与 canSkip 前置；sequence 在等待入口优先于已有宏余项。
- 输入 trace 标识来源。重播时对脚本生成的 sequence/宏输入进行校验，不再次注入，避免
  重复消费或遗留槽位。
- 宏默认开启；关闭时整段按字面提交，不展开重复、不拆换行、不处理 `\e` 或 `@` 系统命令。
  文本框和 sequence 使用同一开关。
- 四个 NF 变体复用现有 timed-input 参数、默认值和 one-input 校验。前端保留连续 NF
  等待之间的上滚意图，跨 timeout、CLEARLINE 和重绘仍有效；普通输入恢复正常跟随。
- 外部输入与 AdvanceTime 以 runtime 收件顺序决定胜负，不按前端时间戳倒推；拒绝旧
  token、旧 epoch 和重放设备事件。
- runtime 保存按键 held、toggle 与 snake latch。普通 GETKEY 不消费 latch，
  GETKEYTRIGGERED 消费一次；完整 down/up 同泵仍可触发。失焦时按参考规则返回 0，
  不误消费状态。
- `AWAIT 0` 也必须产生真实输入泵边界：清旧 latch、请求前端交付设备事件、确认完成，
  再继续；不靠固定 sleep 模拟。
- Web/Tauri 从真实键盘和鼠标事件提交状态，包含左右中键、repeat、blur、visibility 和
  会话切换。TUI 不宣告完整 GETKEY 能力，普通/NF/宏/序列输入继续可用。
- 新增版本化 Environment 能力描述及 `ENV_HAS_CAPABILITY(name[, major])` 查询，返回
  0/1；查询 runtime 已协商能力，不读宿主 OS。
- `GETPLATFORM()` 作为兼容映射：支持保持视口的定时输入返回 0，否则返回 5，并按调用
  位置发 portability diagnostic。明确该值不是实际操作系统。
- 新增输入状态纳入 reset、undo、replay 和快照检查；有未消费 sequence/宏或未完成
  设备泵时拒绝 stable snapshot，不丢弃待处理状态。

### 公共接口与绑定

涉及变更包括 compatibility policy、动态调用/捕获 continuation、InputWait、设备事件
与泵操作、Environment 能力、全局文本背景及错误上下文。

按实际变更递增对应协议、ISA/ABI 或状态格式版本，同步 Schema、Rust 导出、

core 契约完成并提交后，再同步两前端完整 pin、Git rev 和锁文件。记录 C ABI、WASM、
Tauri 的真实 core SHA；不因纯文档或 Git 提交重新构建。

## 4. 验证与验收

### 执行门禁

- 六个子批次分别且仅一次独立重构审查，使用 `refactor-rustyera-code`；全部要求落实后
  才能运行该子批次首条测试。规划阶段只读分析不计作重构审查。
- 测试命令由 **gpt-5.6-terra / low** 测试子智能体执行；其不得修改代码、fixture 或配置。
- core：格式、check、Clippy、最小回归通过后，一次 workspace 全量；修改独立
  runtime-tester 时补其检查。
- TUI：最小 pytest、一次完整 pytest、Ruff；涉及 pin 的改动补源码及打包动态库加载检查。
- Web：最小 Vitest、一次完整 Vitest、类型/lint/格式/build/WASM；涉及 Rust bridge/host
  时补 Rust workspace 门禁和 core-rev 检查。
- 动态验收等待全部相关静态门禁；失败后只修复并定向复验，首次全量结果不改写。

### 行为矩阵

| 范围 | 必须覆盖 |
|---|---|
| 执行策略 | 双 profile；常量/变量/动态表达式；优化开关与暖缓存；极值、除零、postfix；告警去重 |
| RNG | seed 向量；临时重播后恢复；RANDDATA/snapshot/现有保存路径一致；非法状态原子拒绝；固定蛇版差异 |
| 动态调用 | 两种完整文本语法；TRY/CATCH/JUMP；省略与多余参数；副作用不执行；REF、递归、reload |
| STRFORMCHECK | 参数求值失败、解析失败、展开失败；失败前副作用；嵌套捕获、服务等待、资源限额 |
| 数据 API | 空/满/越界数组、角色索引、容量截写、重复 CSV 名称、MAP 顺序及分隔符冲突 |
| 错误钩子 | 正常完成、二次失败、禁用、THROW 与 ERROR 分流、取消/限额、故障后调试 |
| 展示/计时 | 历史背景重绘、透明度与常量/动态边界、负行索引、timer 边界、snapshot/delta |
| 输入 | NF 上滚链；sequence 覆盖与宏余项；宏关闭字面行为；同刻输入/超时；AWAIT0、同泵 down/up、失焦及过期事件 |

双 oracle 分开记录相同输入下的返回值、副作用、诊断和终态；snake 新语法在原版的拒绝
也是明确结果。逐例完成执行、adapter 校验、结构化断言和差分后再进入下一例，首个
未登记差异立即停止。

真实客户端覆盖 Chromium、已安装 Firefox、Safari、Tauri，以及 TUI 的正常输入和
缺能力路径。复用批次 1 驱动，不用 mock、直接改状态或截图替代真实执行。

七个非蛇版项目使用已固定的关键语义 fixture，保持 `emuera.em`；不扩展为七个游戏完整通关。

### 缓存与真实项目规模

- 使用可编译 fixture 验证冷启动、暖启动、单函数修改和动态目标变化；记录耗时、缓存
  字节、compiled/reused 函数数。
- 同输入暖函数缓存应为零重编译；局部修改只失效必要集合。profile、签名、ERD/ALS 或
  ABI 变化不得错误命中。
- 跨端验证 compiled cache 的实际保存、再加载和身份拒绝，不只测试内存中的 compiler cache。
- 复用批次 1 已有完整报告作为历史基线；最终输入冻结后，使用正确配置采集一次真实
  蛇版 TW 的分阶段耗时、峰值内存及编译缺口。
- 区分摄取、分析、编译与报告序列化成本。旧报告包含 `binary=false` 导致的 CHARADATA
  诊断，不能直接用总错误数比较兼容提升。
- 不读取 lazy 二进制索引，不删游戏代码，不以不安全裁剪制造通过。本批不设置虚构的
  全项目缓存加速目标；完整游戏缓存收益仍留批次 4。

### 资源与证据

使用本组独立依赖、产物、游戏副本、端口和会话；先盘点并优先使用已有工具，浏览器
指定实际 executable path，不自动下载安装替代工具。最多两个隔离构建，低于 20 GiB
减少并行，低于 10 GiB 暂停高写入工作。

沿用已明确限定的 core 审计加载阶段观察规则：仅数据摄取、解析/分析/编译和符号准备
阶段允许连续 4 次 5 秒完整采样相同才退出；真实进展或阶段变化重置计数，不能把采样
次数当作进度。报告处理、执行与输入等待仍按连续 2 次相同退出。Browser/Tauri 每五秒
完整 DOM/runtime 快照，连续相同立即失败；TUI 使用稳定等待点规程。该加载阶段例外
不推广至浏览器或原生端到端测试。

矩阵严格 cache-only，缺产物先停止，不逐例隐式重建；记录变化字段并核对产品输入与
构建契约。只重建受实际输入变化影响的产物，已有效证据优先复用。每个队列只有一个
执行器，持续监督至完成、具体失败或用户暂停；不交付无人监督的测试进程。

## 5. 文档、提交与完成标准

本方案与总体计划、分类维护一致的事实及选择：完整 CALLSTR 文本、EXISTVAR 解析模式、
STRFORMCHECK 实际展开、MAP 无转义、全局历史背景和 RNG 选择。实施进度不得写成已验证
语义，也不得覆盖历史 oracle 的原始结果。

- 每个功能/修复点单独提交，共享基础单列；跨组件分别提交，附依赖和验证绑定。
  合并审查或测试不等于合并 commit。

  **不写实施日志及批次总览的中间状态**，不另建中间实施或验收文档。
- 整批结束后统一记录实际改动、审查结论、首次全量、定向复验、差异、未验证项及
  源码/产物身份。
- 根 `CHANGELOG_PENDING.md` 只追加已验证产品功能和修复；文档、测试及流程调整不记入。
- 不调整产品发布版本、不推送、不合并主线，不自动进入批次 3。

### 原版极值负号的显示边界

固定原版 `MinusInt.GetIntValue` 在对 `Int64.MIN` 取负时调用 `PrintSystemLine`；
其结果仍为 `Int64.MIN`。Rust 保持原有原版算术行为，不向游戏历史注入该系统行，
也不新增原版算术告警。该项按精确原始输出登记为显示与历史查询差异；数值、终态与
副作用仍独立断言，原始 `different` 不改写为等价。
