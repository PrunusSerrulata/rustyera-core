## 1. 文件、加载与大小写规则

### 1.1 文件类型
- `*.ERB`：脚本主体，定义 `@函数/事件`、`$标签`、普通语句。由 `ErbLoader.cs` 加载。
- `*.ERH`：头文件，只允许预处理/声明类内容（如 `#DIM`、`#DEFINE`、`#FUNCTION` 等）。由 `ErhLoader.cs` 加载。

### 1.2 基本结构
- 一个脚本文件通常由多个 `@函数名` 块组成。
- `@` 开头定义可调用函数/事件标签。
- `$` 开头定义当前函数内部可 `GOTO` 的局部标签。
- 绝大多数语句以“**一行一条**”为单位解析；多行文本拼接要靠续行块（见下文）。

### 1.3 大小写规则
源码并不是“永远大小写不敏感”，而是**受配置项 `IgnoreCase` 控制**：
- `Config.IgnoreCase == true` 时，标识符、关键字、函数名等按 `StringComparison.OrdinalIgnoreCase` 比较；
- `Config.IgnoreCase == false` 时，改为大小写敏感。

源码依据：`Config.cs`、`ErbLoader.cs`、`ErhLoader.cs`、`LogicalLineParser.cs`。

> 实务上，本项目脚本大多按“不区分大小写”使用；但文档编写时应记住：**这是配置行为，不是语法硬编码**。

## 2. 行、注释与续行

### 2.1 注释
源码确认：**行首/行内 `;` 才是标准注释起始符**。
- `LexicalAnalyzer.SkipWhiteSpace` 在读到 `;` 时直接把余下部分视为注释；
- 词法器中**未发现 `//` 注释规则**，因此不能把 `//` 当成源码级标准注释语法来写进规范。

```erb
; 这是注释
PRINTFORM Hello ; 这一行后半段也是注释
```

源码依据：`LexicalAnalyzer.cs`。

### 2.2 续行块
`EraStreamReader.ReadEnabledLine` 支持一种**块式续行**：
- 若某一物理行（去前导空白后）只有一个 `{`；
- 则后续多行会被拼接成同一条逻辑行；
- 直到遇到只包含 `}` 的结束行。

这不是 C 风格代码块，而是**文本级续行机制**。

```erb
{
PRINTFORM 这一大段
会在读取阶段被拼接为
同一条逻辑行
}
```

源码依据：`EraStreamReader.cs`。

### 2.3 空白字符
- 半角空格、Tab 可正常跳过；
- 全角空格是否允许，受 `SystemAllowFullSpace` 配置控制。

源码依据：`LexicalAnalyzer.cs`。

## 3. 标签与函数定义

### 3.1 `@函数名`
`@` 定义函数/事件入口。解析入口在 `LogicalLineParser.ParseLabelLine`。

```erb
@SPIRIT_GET_BASE_RESOURCE(VIS_C, 表示形式 = "", 服装 = "")
#DIM DYNAMIC VIS_C
#DIMS DYNAMIC 表示形式
RETURN
```

真实示例：`ERB/魔改内容/GRAPH系.ERB:6-18`

说明：
- `@` 后首先必须是标识符；
- 其后可跟参数列表；
- 若标签名被识别为事件名/系统名，则会被标记为事件或系统函数。

源码依据：`LogicalLineParser.cs`、`ErbLoader.cs`。

### 3.2 `$标签名`
`$` 定义函数内部的局部跳转标签，供 `GOTO` / `TRYGOTO` 使用。

```erb
$WEATHER_INFO
PRINTFORM ― %GET_WEATHER(ARG:2)% ―
```

真实示例：`ERB/魔改内容/qol/qol_weather.ERB:396-398`

说明：
- `$标签` 不能像 `@函数` 那样带参数；
- 标签解析为 `GotoLabelLine`，作用域是**当前函数**。

源码依据：`LogicalLineParser.cs`、`GotoLabelLine.cs`、`CalledFunction.cs`。

## 4. 方括号预处理指令

这套语法由 `ErbLoader.PPState` 处理，**写法是 `[IF ...]`，不是 `#IF`**。

支持的完整列表：

| 指令 | 作用 | 备注 |
|---|---|---|
| `[SKIPSTART]` | 开始跳过区块 | 直到 `[SKIPEND]` |
| `[SKIPEND]` | 结束跳过区块 | |
| `[IF 宏名]` | 宏已定义则启用，否则禁用 | 宏来自 `#DEFINE` |
| `[ELSEIF 宏名]` | 预处理分支 | |
| `[ELSE]` | 预处理分支 | |
| `[ENDIF]` | 结束预处理分支 | |
| `[IF_DEBUG]` | 仅调试模式启用 | `Program.DebugMode` |
| `[IF_NDEBUG]` | 非调试模式启用 | |

示例：

```erb
[SKIPSTART]
@EVENTEND
#PRI
...
[SKIPEND]
```

真实示例：`ERB/fromEN/Addition/Marriage/Add_Marriage_Concubinage.ERB:1-16`

```erb
[IF DEBUG]
...
[ENDIF]
```

真实示例：`ERB/魔改内容/QOL_IMAGE.ERB:1547-1549`

源码依据：`ErbLoader.cs`。

## 5. `#` 指令（声明/事件属性）

## 5.1 适用位置
- 在 `ERH` 中：`#DEFINE`、`#DIM*`、`#REF*`、`#FUNCTION*` 等用于声明；
- 在 `ERB` 中：紧跟在 `@函数` 后的 `#...` 行用于修饰该函数或定义其私有变量。

源码依据：`ErhLoader.cs`、`LogicalLineParser.cs`。

## 5.2 事件属性类指令（ERB 标签后）

| 指令 | 作用 | 限制 |
|---|---|---|
| `#PRI` | 事件函数放入优先组 | 仅事件函数 |
| `#LATER` | 事件函数放入延后组 | 仅事件函数；与 `#PRI` 冲突 |
| `#SINGLE` | 事件返回 `1` 时切到下一组 | 仅事件函数 |
| `#ONLY` | 事件放入 only 组，并忽略 `PRI/LATER/SINGLE` | 仅事件函数 |

事件组顺序由 `LabelDictionary` 固定为：`ONLY -> PRI -> 普通 -> LATER`。
`#SINGLE` 的特殊行为在 `ProcessState.Return` / `CalledFunction.ShiftNextGroup` 中实现。

真实示例：

```erb
@EVENTLOAD
#LATER
...
```

示例出处：`ERB/SYSTEM.ERB:100-106`

```erb
@EVENTEND
#PRI
...
```

示例出处：`ERB/fromEN/Addition/Marriage/Add_Marriage_Concubinage.ERB:2-6`

> `#SINGLE`、`#ONLY` 在本仓库 `ERB/` 中未检索到现成实例，但源码已实现。

源码依据：`LogicalLineParser.cs`、`LabelDictionary.cs`、`ProcessState.cs`、`CalledFunction.cs`。

## 5.3 返回类型与局部尺寸

| 指令 | 含义 |
|---|---|
| `#FUNCTION` | 当前 `@` 标签声明为**整型返回**用户函数 |
| `#FUNCTIONS` | 声明为**字符串返回**用户函数 |
| `#FUNCTIONF` | 声明为**浮点返回**用户函数 |
| `#LOCALSIZE n` | 预分配 `LOCAL` 长度 |
| `#LOCALSSIZE n` | 预分配 `LOCALS` 长度 |
| `#LOCALFSIZE n` | 预分配 `LOCALF` 长度 |

真实示例：

```erb
@SPIRIT_颜像索引(ARGS)
#FUNCTIONS
RETURNF @"颜%ARGS%"
```

示例出处：`ERB/魔改内容/GRAPH系.ERB:203-206`

```erb
#LOCALSIZE 1
#LOCALSSIZE 1
```

示例出处：`ERB/魔改内容/GRAPH系.ERB:17-19`

源码依据：`LogicalLineParser.cs`、`FunctionIdentifier.cs`。

## 5.4 变量声明类指令

### 5.4.1 基本类型变体
| 指令 | 类型 |
|---|---|
| `#DIM` | 整型 |
| `#DIMS` | 字符串 |
| `#DIMF` | 浮点 |
| `#REF` | 整型引用参数 |
| `#REFS` | 字符串引用参数 |
| `#REFF` | 浮点引用参数 |

### 5.4.2 常见限定词
`UserDefinedVariableData.Create` 还能识别多种限定词，常见有：
- `CONST`
- `DYNAMIC`
- `STATIC`
- `GLOBAL`
- `SAVEDATA`
- `CHARADATA`
- `REF`
- `OUT`

但它们之间并非任意可组合，源码中有大量互斥检查（例如 `CONST` 不能与 `DYNAMIC` 共存）。

真实示例：

```erb
#DIM CONST NOW_VERSION = 20260630
#DIMS CONST eraTW_Version = "4.981"
#DIM SAVEDATA modding_version
```

示例出处：`ERB/DIM.ERH:2-5`

```erb
#DIM DYNAMIC VIS_C
#DIMS DYNAMIC 表示形式
```

示例出处：`ERB/魔改内容/GRAPH系.ERB:7-10`

> `#DIMF` / `#REF` / `#REFS` / `#REFF` / `#FUNCTIONF` / `#LOCALFSIZE` 在本仓库脚本中未检索到现成实例，但源码已实现。

源码依据：`UserDefinedVariableData.cs`、`LogicalLineParser.cs`、`ErhLoader.cs`。

## 5.5 `#DEFINE`（ERH 头文件）
`ERH` 头文件支持 `#DEFINE 宏名 替换内容`。
- `ErhLoader` 会把其注册到标识符字典；
- `[IF 宏名]` / `[ELSEIF 宏名]` 检查的就是这类宏；
- 源码里尝试解析“函数式宏参数”，但最终会抛出 `CanNotDeclaredFuncMacro`，因此**本 fork 实际上只支持普通对象式宏，不支持函数式宏定义**。

源码依据：`ErhLoader.cs`。

## 6. 字面量、标识符与字符串

## 6.1 标识符
词法器通过 `ReadSingleIdentifierROS` 读取标识符，遇到空白、运算符、括号、引号、`@`、`;` 等分隔字符即停止。

源码依据：`LexicalAnalyzer.cs`、`IdentifierWord.cs`。

## 6.2 整数字面量
支持：
- 十进制：`123`
- 十六进制：`0xFF`
- 二进制：`0b1010`
- 可带前导正负号
- 还支持 `e/E`、`p/P` 后缀指数形式（源码实现层面支持）

源码依据：`LexicalAnalyzer.ReadInt64`、`LiteralIntegerWord.cs`。

## 6.3 浮点字面量
支持：
- `1.5`
- `0.25`
- `1.0e-3`

词法上，数字串后带 `.` 时会按浮点处理。

源码依据：`LexicalAnalyzer.ReadDouble`、`LiteralFloatWord.cs`。

## 6.4 普通字符串字面量
普通表达式里的字符串使用双引号：

```erb
CALL IMAGE_CHARA_OVERRIDE("特殊服装", VIS_C,,, TARGET_CHARA)
```

支持的转义（`ReadString` / `AnalyseFormattedString`）：
- `\s` -> 半角空格
- `\S` -> 全角空格
- `\t` -> Tab
- `\n` -> 换行
- `\e` -> 文字 `\e`
- 其他 `\x` -> 直接输出 `x`

源码依据：`LiteralStringWord.cs`、`LexicalAnalyzer.cs`。

> 单引号字符串不是通用表达式字面量规则；它只在少数特定语境（例如某些参数解析模式）下被允许，不应把 `'...'` 当作通用 ERB 字符串写法。

## 7. FORM 字符串与插值语法

这是本 fork 最容易写错、也最值得单独说明的一部分。

## 7.1 两种 FORM 场景

### A. 命令参数型 FORM
很多 `...FORM` 命令（如 `PRINTFORM`、`DATAFORM`、`THROW`）把“**整行剩余文本**”按 FORM 字符串解析：

```erb
PRINTFORM %CALLNAME:TARGET%紧紧闭上眼睛…
DATAFORM 抓紧%CALLNAME:TARGET%的屁股
THROW 未设置正确的获取内容。
```

### B. 表达式型 FORM 字符串字面量
在表达式内部，FORM 字符串写作 `@"..."`：

```erb
RETURNF @"颜%ARGS%"
CALL SPIRIT_特效切分(Version, VIS_C, @"%表示形式%_%特效:LOCAL%_{NO:VIS_C}")
```

真实示例：
- `ERB/魔改内容/GRAPH系.ERB:205`
- `ERB/魔改内容/GRAPH系.ERB:511-513`

源码依据：`LexicalAnalyzer.cs`、`StrFormWord.cs`、`StrForm.cs`、`FormStrEndWith.cs`。

## 7.2 `%...%`：字符串插值
`%...%` 内部会被当成**字符串表达式**求值；若类型不是字符串，`StrForm` 会报错。

语法：
```text
%字符串表达式[,宽度[,LEFT|RIGHT]]%
```

例：
```erb
%CALLNAME:TARGET%
%RESULTS%
%CALLNAME:TOINT(CID_LIST:LOCAL),9,LEFT%
```

真实示例：`ERB/魔改内容/qol/qol_update.ERB:663-667`

### 与“宏展开”的区别
很多旧资料会把 `%变量%` 说成“宏展开”，但就**本源码实现**而言，它是：
- 先由 `StrForm` 解析；
- 再在运行期求值；
- 本质属于**FORM 字符串插值**，不是 `#DEFINE` 那种预处理宏替换。

## 7.3 `{...}`：数值插值
`{...}` 内部会被当成**数值表达式**求值；允许整数或浮点。

语法：
```text
{数值表达式[,宽度[,LEFT|RIGHT]]}
```

例：
```erb
@"日语交流用画蛇添足版CH{NOW_VERSION}"
@"%表示形式%_%LOCALS:LOCAL%_{NO:VIS_C}"
```

真实示例：
- `ERB/DIM.ERH:4`
- `ERB/魔改内容/GRAPH系.ERB:520`

## 7.4 `\@条件?真串#假串@`
源码实现了 `YenAtSubWord` 条件片段：
- 先计算 `条件`（整数表达式，0 为假）；
- 真时取 `?` 与 `#` 之间的 FORM 子串；
- 假时取 `#` 与结尾 `@` 之间的 FORM 子串；
- 若缺少 `#`，假分支按空串处理，并给出警告。

语法：
```text
\@条件?真分支#假分支@
```

源码依据：`LexicalAnalyzer.AnalyseYenAt`、`YenAtSubWord.cs`、`StrForm.cs`。

## 7.5 三连符号快捷记法
在 FORM 字符串内，若关闭 `SystemIgnoreTripleSymbol`，则三连相同字符会被解释为快捷插值：
- `***` -> `NAME:TARGET`
- `+++` -> `CALLNAME:MASTER`
- `===` -> `CALLNAME:PLAYER`
- `///` -> `NAME:ASSI`
- `$$$` -> `CALLNAME:TARGET`

源码依据：`CharStream.TripleSymbol`、`TripleSymbolSubWord.cs`、`StrForm.cs`。

## 8. 运算符与优先级

## 8.1 源码中实际存在的运算符

### 算术/字符串
| 运算符 | 含义 | 备注 |
|---|---|---|
| `+` | 加法 / 字符串拼接 | `string + string` 合法 |
| `-` | 减法 | |
| `*` | 乘法 / 字符串重复 | `string * int` 或 `int * string` 合法 |
| `/` | 除法 | |
| `%` | 取模 | |

### 比较
| 运算符 | 含义 |
|---|---|
| `==` | 等于 |
| `!=` | 不等于 |
| `>` | 大于 |
| `<` | 小于 |
| `>=` | 大于等于 |
| `<=` | 小于等于 |

### 逻辑
| 运算符 | 含义 |
|---|---|
| `!` | 逻辑非 |
| `&&` | 逻辑与 |
| `||` | 逻辑或 |
| `^^` | 逻辑异或 |
| `!&` | 逻辑 NAND |
| `!|` | 逻辑 NOR |

### 位运算
| 运算符 | 含义 |
|---|---|
| `~` | 按位取反 |
| `&` | 按位与 |
| `|` | 按位或 |
| `^` | 按位异或 |
| `<<` | 左移 |
| `>>` | 右移 |

### 赋值/自增减
| 运算符 | 含义 |
|---|---|
| `=` | 赋值 |
| `+=` `-=` `*=` `/=` `%=` | 复合赋值 |
| `<<=` `>>=` `&=` `|=` `^=` | 位复合赋值 |
| `++` `--` | 前置/后置自增减 |
| `'=` | **字符串赋值** |

### 三元运算符
源码中的三元不是 `? :`，而是：

```text
条件 ? 真表达式 # 假表达式
```

这是由 `OperatorCode.Ternary_a` / `Ternary_b` 实现的。

源码依据：`OperatorCode.cs`、`OperatorManager.cs`、`OperatorMethodManager.cs`、`ExpressionParser.cs`。

## 8.2 本 fork **没有** `**`
用户常把某些 era 系资料里的 `**` 幂运算写进语法表，但本仓库源码：
- `LexicalAnalyzer.ReadOperator` **没有** `**`；
- 幂运算以命令 `POWER` 提供，而不是表达式运算符。

因此本 fork 的权威语义应写成：**没有 `**` 运算符**。

## 8.3 优先级（高到低）
根据 `OperatorCode` 里的优先级位与 `ExpressionParser` 的归约逻辑，可整理为：

1. 后置 `++ --`
2. 前置 `+ - ! ~ ++ --`
3. `* / %`
4. `+ -`
5. `<< >>`
6. `> < >= <=`
7. `== !=`
8. `& | ^`
9. `&& || ^^ !& !|`
10. `? ... # ...`
11. 赋值类（赋值不作为普通表达式链式运算使用，而在赋值语句语境中单独处理）

## 8.4 短路规则
逻辑运算实现位于 `OperatorMethodManager`：
- `&&` 使用 C# 的 `&&`
- `||` 使用 C# 的 `||`

因此运行时具有短路特性：
- 左侧已足以确定结果时，右侧不会求值。

## 8.5 前后置自增减的限制
- 只能用于变量；
- 常量不可 `++/--`；
- 后置版本返回修改前的值。

源码依据：`OperatorMethodManager.cs`。

## 9. 变量声明基础

> 这里只讲“语法入口”和“声明方式”，不展开完整变量体系清单。

## 9.1 全局/头文件声明
通常放在 `ERH`：

```erb
#DIM CONST NOW_VERSION = 20260630
#DIMS CONST eraTW_Version = "4.981"
#DIM SAVEDATA modding_version
```

示例出处：`ERB/DIM.ERH:2-5`

特点：
- 由 `ErhLoader` 在脚本加载阶段处理；
- 可声明常量、存档变量、全局变量等。

## 9.2 函数私有变量
紧跟 `@函数` 后使用 `#DIM/#DIMS/#DIMF`：

```erb
@SPIRIT_GET_BASE_RESOURCE(...)
#DIM DYNAMIC VIS_C
#DIMS DYNAMIC 表示形式
#LOCALSIZE 1
#LOCALSSIZE 1
```

示例出处：`ERB/魔改内容/GRAPH系.ERB:6-19`

特点：
- 由 `FunctionLabelLine.AddPrivateVariable` 挂到当前函数；
- `DYNAMIC` 私有变量在作用域进入/退出时 `ScopeIn/ScopeOut`。

## 9.3 运行期局部声明 `VARI` / `VARS`
`LogicalLineParser.ParseLine` 对 `VARI` / `VARS` 有专门解析：
- `VARI`：定义整型局部变量/数组；
- `VARS`：定义字符串局部变量/数组。

它们不是 `#` 指令，而是普通语句级声明。

源码依据：`LogicalLineParser.cs`。

## 9.4 数组维度
`#DIM*` / `#DIMS*` 等可以声明：
- 标量
- 1 维数组
- 2 维数组
- 3 维数组

长度信息记录在 `UserDefinedVariableData.Lengths` / `Dimension` 中。

## 9.5 静态与动态
- `STATIC` / 默认静态：随定义存在；
- `DYNAMIC`：仅私有变量可用，离开作用域后释放。

源码依据：`UserDefinedVariableData.cs`、`FunctionLabelLine.cs`。

## 10. 与源码不符处的校正说明

本项目文档编写时，以下几项必须按源码修正：

1. **预处理分支不是 `#IF/#IFDEF/#IFNDEF`**，而是 `[IF] / [ELSEIF] / [ELSE] / [ENDIF]`，并额外支持 `[IF_DEBUG] / [IF_NDEBUG]`。
2. **标准注释符是 `;`，未发现 `//` 注释词法支持**。
3. **三元运算符是 `? #`，不是 `? :`**。
4. **本 fork 没有 `**` 幂运算符**；幂运算使用 `POWER` 命令。
5. **`%...%` 是 FORM 字符串运行期插值，不是 `#DEFINE` 预处理宏**。
6. **`#NOSKIP` 不存在**；实际是普通语句 `NOSKIP` / `ENDNOSKIP`。
7. **`DO/LOOP` 的源码实现没有 `UNTIL` 关键字分支**；本 fork 实际语义是 `DO ... LOOP <整数条件>`。
